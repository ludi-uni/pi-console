# Pi Console 0.5.4

0.5.4 is a documentation-cleanup and stability-fix release. **Nothing has been published, deployed, or restarted yet.** The notes below describe what is intended for the package.

## User-facing changes

- **Pi 1.5.0 support**: the supported range is now stable `0.99.2–1.5.0`. Real SDK initialization, extension integration and direct history reads were checked on 1.5.0 and 1.4.0; isolated package installation and start/stop were also checked on 1.5.0, without model calls. Stable versions within the range are supported, but not every version was individually exercised. Prereleases and versions newer than 1.5.0 remain excluded.
- **Discard queued**: while the queue is paused (Stop, failed or unconfirmed delivery, restart), you can now discard every pending item at once instead of removing them one by one. The action is refused while an item is mid-dispatch, and the confirmation explains that removing a queued item does not undo a send that already reached Pi.
- **Stable notification ordering**: while the Activity inbox is open, cards keep their displayed order even when the server re-sorts by urgency. If a poll removes a session, a disabled tombstone holds the slot so another card cannot slide under the pointer and capture a click. Closing and reopening the inbox restores the current order.
- **Execution copy**: failed/interrupted/blocked/decision nodes offer **Copy context**, and failed or issue events offer **Copy log**. Event copies include IDs, type, time, status, source and the full payload; node copies append the related events that carry the actual error text. If automatic clipboard access is unavailable, a manual-select fallback appears.

## Dots and local MCP temporarily unavailable

This release temporarily excludes Pi Console's Dots and MCP integrations (local resume, folders, Pi control and readonly). Connection settings, MCP endpoints and the `local-resume` CLI are unavailable; previous environment variables or stored settings do not re-enable them. Code and saved configuration are preserved for later work. Normal Pi sessions, Pi's own MCP extension, Chat, Execution, voice input and remote connections remain available. `owner-login` remains for local identity verification used by voice settings and other non-MCP management. Dots/local-MCP design and verification documents are historical development records, not activation instructions for this release.

## Package contents

Documentation in the npm package is limited to top-level Markdown (`docs/*.md`), example screenshots (`docs/images/`) and release notes (`docs/releases/*.md`). Design Markdown remains as historical reference; local verification archives, logs, scripts and JSON evidence are preserved on disk but excluded from distribution.

## Verification status

- `npm test`: 517 passed / 11 skipped, no failures (skips are environment-dependent pre-existing cases).
- Browser checks ran in Windows Chrome headless; focused feature checks use mocked APIs. The 0.5.4 PWA cache update and offline shell were also checked. Physical Safari / iOS, Firefox / Edge, real screen readers, and acceptance flows involving model calls or production external connections were not exercised.
- No production deployment, publish, or server restart has been performed.

## Release procedure note

The working tree already contains many pre-existing evidence files, so `git add .` is unsafe. Stage changes individually; commit and push are left for a separate step.

## Known notes

- Upgrading an older Windows Startup installation requires the [pre-upgrade backup and migration](../upgrade-storage.md) step before npm updates.
- Remote connections remain available only on owner-configured connections; treat the feature as not yet production-applied and run a connection test in your environment.
