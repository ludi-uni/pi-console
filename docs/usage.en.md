# Using Pi Console

[Home](../README.en.md) · [日本語](usage.ja.md)

## Workspaces and sessions

1. Run `/pi-console` in Pi and open the displayed URL. The default port is `31717`; use `/pi-console 31719` to choose another port. `/pi-console stop` stops the managed server; it is a detached background process that survives Pi exit or reload, and `/pi-console status|restart|port` or `scripts\pi-console.ps1 <command>` manage the same instance outside Pi.
2. In **Workspaces**, select an existing workspace or add one via the **Add workspace** disclosure with **Browse folders** (or an absolute path) and **Add & open**. On mobile, **Add a workspace** above the list jumps to the registration form. A workspace is a server-local working directory, not a separate “project” entity or a folder on your phone.
3. Select or create a session, then send Pi prompts in **Chat**. Idle **Send** switches to **Stop** while Pi runs; **Queue after run** holds the message in a console-owned pending list above the composer — edit its text (attachments are kept), or remove it, until it is dispatched to Pi; **Steer now** sends immediately and cannot be edited or recalled. Queued items persist across server restarts, but nothing sends while the queue is paused: **Stop**, a failed or unconfirmed dispatch, or a restart leaves items **held** until you choose **Resume queued** (sends the held item and the rest, in order), remove an item individually, or **Discard queued** to drop every pending item at once. **Discard queued** asks for confirmation first and refuses while an item is mid-dispatch; discarding cannot undo a send that already reached Pi. Queued items must be removed or resumed before the session can be closed or recycled. The queue holds at most 16 items per session (64 MiB total) and is durable under the Console data dir — nothing is lost on restart, and nothing is sent until **Resume queued**. A held item whose delivery was unconfirmed warns before resending, since it may already have reached Pi. Choose its model and thinking level in the session. **Context** shows Pi's reported usage after a reply. An unprompted new session exists only on the current server until its first prompt creates a Pi session file.

**Manage workspace** can rename, pin or remove a registration; **Remove from Console** detaches only the registration — the folder and its Pi sessions stay on disk. The folder browser can create a subfolder in the open directory. **Open on host PC** opens the registered local folder on the host's interactive Windows desktop, even when clicked from a phone; it does not open the phone's file manager.

## Chat, attachments and previews

- Open **🎙** at the bottom-left of the prompt, choose a language and select **Start listening** to use this device's microphone. Recognition stops after 60 seconds; review confirmed text and select **Insert into prompt** to add it at the cursor without replacing existing text or attachments. It never sends a prompt automatically. Canceling, switching sessions/views or leaving the page aborts recognition. Web Speech API requires a compatible browser and HTTPS or a secure local connection; audio may be sent to the browser provider, not necessarily processed locally. Use your keyboard's dictation if unsupported.
- **Local speech recognition (speech.cpp)**: when the owner enables it on the Console PC, browsers without Web Speech API can pick the local engine. Recording is converted to a 16 kHz mono WAV and posted once to the same-origin `/api/voice/transcribe` (handled by the local model on the Console server; audio and results are never stored). Language offers Japanese, English and **Auto-detect**. Stopping releases the microphone immediately; while transcribing you can **Cancel** (late results are never inserted).
- The **Voice input** settings section stays in-app and uses a terminal-free onboarding card: **Prepare** → capacity/requirement confirmation → **Download and prepare** → a REAL **native confirmation on the Console PC** (speech download/run only — no admin grant) → real phase + elapsed monitoring/cancel → ready → a local-only audio test (never auto-sent). The default model is **0.6B** (~0.84 GB, runtime extra); paths/model/existing executable live under the collapsed **Advanced options**. A remote device can ask the host to confirm but can never approve from the browser, and reloading only reconciles a pending request — it never spawns a dialog or download. Unsupported/noninteractive/unmanaged environments are shown clearly; the old owner-login command survives only inside the collapsed **Troubleshooting** area. No download starts until BOTH browser consent and native approval. Requirements: Windows x64 + Vulkan loader (the loader check is not GPU proof).
- The queue list has a bounded height and scrolls independently without pushing **Queue**, **Stop** or the composer out of view. Desktop Enter sends; Shift+Enter inserts a newline. On touch devices Enter inserts a newline; tap **Send** to submit. Ctrl+Enter / ⌘+Enter also send.
- Unsent text and attachments are scoped by workspace/session and saved in this browser's IndexedDB, restoring after switching or reloading. They do not sync to other devices or send automatically. An acknowledged submission clears only its matching input, preserving newer edits. Storage failures show a warning; leaving with uncommitted changes also requests confirmation. Browser data clearing, quota restrictions or eviction can prevent retention. On shared devices, remember that draft text and attachment bytes remain on the device.
- Attach up to four small UTF-8 text files or PNG/JPEG/GIF/WebP images with the **📎 Attach** button overlaid at the bottom-left of the prompt box; chosen files appear as removable chips. Pi-provided thinking and tool calls appear separately; tap a command to expand its bounded invocation. **Instructions** jumps to past user prompts; **Copy all** is below an assistant answer.
- Assistant answers render Markdown tables, lists and fenced code. Raw HTML and remote images are not rendered.
- `.html` / `.htm` links open a separate consent tab. CSS, JavaScript (including inline code), images, audio/video and fonts have independent permissions, all defaulting OFF. Review the entry HTML, candidate files beneath its directory, hashes and scope; select the permitted kinds and confirmation checkbox, then explicitly run the isolated preview. Grants last up to five minutes and stop on revoke or when leaving the tab; reload requires fresh consent, as do file changes after review. Supported local files: JS/CSS; PNG/JPEG/GIF/WebP images; WAV/MP3/OGG/OGA/OPUS/M4A audio; MP4/WebM video; WOFF/WOFF2/TTF/OTF fonts. HTML image/srcset/media references and CSS image/font URLs are embedded; fonts also require CSS consent. Autoplay attributes are removed, and playback depends on browser codecs. External URLs/CDNs, API requests, SVG/PDF, additional HTML documents, ES modules/import maps and Node.js execution are unsupported. Per-file limits: HTML/JS/CSS 256 KiB, images 4 MiB, audio/video 8 MiB, fonts 2 MiB. At most 64 resources, 16 MiB total raw bytes including HTML, 512 scanned entries and depth 8. Put the page and its required files in a dedicated directory if these limits are exceeded.
- Paths in assistant prose, Markdown links or inline code to `.txt`, `.md`, `.markdown`, common source/configuration files, PNG/JPEG/GIF/WebP images and MP4/WebM videos open read-only previews inside the selected workspace. Workspace-local Markdown images open on click; remote images never load automatically. Plain prose paths containing spaces are recognized when they include a directory prefix.
- Text previews reject paths outside the workspace (including symlink escapes), binary or unsupported files, and UTF-8 files above 256 KiB. Images are limited to 20 MiB and videos to 512 MiB; file signatures must match their extensions. Video seeking uses byte ranges and playback depends on browser codec support. The console cannot edit files; its media endpoint does not prevent a browser from saving them. **Copy** copies original text, not rendered Markdown. Code has line numbers; `src/main.ts:42`, `src/main.ts:42:8` and `src/main.ts#L42` jump to a line. Follow links within previews and use **Back** to return.

## Execution and Orchestrator

- **Execution** shows Pi tools, observed foreground pi-subagents and session-bound Orchestrator activity. Relationships that cannot be verified remain **Unattached**. There is no approval UI. While a tool runs, its observed program or command appears when Pi supplies it.
- **Activity** shows subagents, pending input, completion results and recent issues, dismissible for up to 24 hours while server state lasts. The top Activity inbox can be collapsed while keeping its counts visible; the header alert button opens it. While the inbox is open, card order stays fixed even when a server poll re-sorts by urgency; a session removed by that poll remains as a disabled tombstone until you close the panel, so a card cannot slide under your pointer and capture the click. Closing and reopening the inbox shows the current order. Tool/run failure toasts disappear after about seven seconds or on dismissal, without shifting the UI. **View in Execution** opens the exact event in the history, which remains available afterwards. **Inspect background result** requests only the bounded final output available from the session's pi-subagents extension; expired artifacts cannot be reconstructed. Failed, interrupted, blocked and decision nodes offer **Copy context**, and failure-type events offer **Copy log**; both copy the full diagnostics (IDs, type, time, status, payload). When the browser cannot copy automatically, select the shown text and copy it manually.
- With a compatible ludi-agent-kit installed, start a separate Orchestrator run from **Execution**, bound to the selected Pi session and workspace. Kit model routing differs from the Pi session model and may incur provider charges. For a new session, Pi first generates a short acknowledgement to save its file; when the kit finishes, Pi receives a bounded report and saves a normal assistant answer. These Pi calls also have model costs. Progress appears live in Chat but is not persisted as chat history; detail is reconstructed from kit state in Execution. The Chat report, Execution run card and new-run form can be collapsed.
- Pi prompts pause while the kit owns the same session. Answer questions in the pending-question card inside **Chat**, by choosing an option or entering free text. **Execution** links to the same card; switching views or rotating the device preserves an unsent answer. The kit resumes after all pending questions are answered and may make additional model calls. If the continuation fails while that same answered run remains resumable, **Retry continuation** starts it again without resending the answer; retrying may also call models. **Continue Pi chat while kit is paused** lets you use Pi without discarding that run; Pi prompts pause again while a retry is running. Answers are retained in the kit's repository-scoped decision memory. If the kit finishes but saving its final report to Pi fails, **Retry saving report to Pi** retries only the report, not the kit work, but may call a Pi model. A new kit run cannot start in that session until the report failure is resolved. When prior delivery cannot be ruled out, it refuses a blind resend and asks you to inspect the Pi session. After inspecting the Pi session and the report in Execution, choose **Mark report handled after inspection** if you want to proceed without resending. Confirming marks delivery as *unverified*, disables retry, and allows another kit run. Failed report state and the uncertain-dispatch marker are stored under the data directory's `report-recovery/` and restored after a server restart; recovery never automatically resends the report. Recycling that session or removing its workspace is blocked while a report remains unresolved. Browser attachments and **Stop** do not apply to kit runs; the console cannot cancel kit runs. **Stop** is disabled while the kit saves its report to Pi so that report delivery cannot be interrupted. For ordinary Pi prompts, **Stop** preserves and pauses the Console-owned queue, clears Pi's already-submitted steering queue, and sends `abort` to Pi.

## Mobile, notifications and settings

On a phone, navigate Workspaces → sessions → Chat / Execution. In-app links and browser Back/Forward return to the lists without stopping Pi. Browser reconnects do not kill a worker. Installing the PWA does not make Pi available offline.

**Settings** offers session view, appearance and Codex-compatible pet controls. Its language setting covers settings, navigation and key chat controls, **not the entire application or conversation content**. Pets are discovered from separately installed `pet.json` and spritesheet packages and can be dragged. **Sessions → Automatic cleanup** moves Pi session files older than a chosen number of days to the server's Windows Recycle Bin (off by default). Pi sessions may be shared with other apps. Sessions can also be recycled individually.

**Sessions** completion notifications work only while the tab remains open but hidden. Permission is requested when enabled; there is no “almost finished” prediction or closed-browser notification. **Orchestrator settings** registers up to 16 models with arbitrary display names, editable without changing their stable routing IDs. Checkboxes allow planning/investigation, coding/testing, review, image inspection and browser automation. New registrations start with no permissions; select them in capability routes after granting the required uses. Both the capability and agent role must be allowed (image review needs image and review permission; image-taking planners/scouts need image and planning permission). Image inspection also requires the model’s image-input support. These are model-routing restrictions, not tool or OS permissions. Capability/cost classes are declarations used by kit routing: keep unknown costs at `high`, and mark `free` / `included` only when verified. Legacy kit assignments remain in a separate collapsed section and are not restricted by the new registrations' checkboxes. Registrations and their routes persist in the Console data directory's `orchestrator-models.json`, applying only to runs started/resumed through Console, not the kit CLI or Pi chat model. Capabilities can be created, reordered, edited, deleted (custom ones), disabled and restored (built-ins). Fallback order uses arrow buttons rather than comma-separated IDs; disabling a built-in capability may make agents that require it unavailable. See [Operations and development](operations.en.md) for configuration and storage details.
