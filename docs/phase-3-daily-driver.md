# Phase 3 — Daily Driver UX

Phase 0–2 source boundaries, canonical events, Pi process ownership, and fact-based relationships remain unchanged. This phase adds UI and lightweight metadata only; no event source, database, approval protocol, external bind, or durable execution log.

## Workspace UX

A workspace is one server-local directory used as Pi's working directory. There is no separate project entity; the UI consistently calls it a workspace.

Workspace picker groups pinned, five recent unpinned, and remaining entries under All, with name/path filtering. Current path, rename, pin/unpin, last-opened timestamp, and missing-path indication are shown. Missing paths cannot be selected. Opening a workspace updates `lastOpenedAt`; adding requires an existing absolute directory and resolves its real path. The new Browse folders dialog lets desktop/mobile users navigate the **server machine's** drive roots, home and current directory, filter immediate subfolders, use breadcrumbs/Up, then explicitly choose a directory before creating a workspace. The authenticated same-origin API returns directory names/paths only, no file content, and rejects UNC/device/relative paths. Mapped network drives are omitted from the local-only location list. Scanning and results are bounded. A browser/phone's own local filesystem is not accessible through this picker. Existing array-format `.pi-console/workspaces.json` loads without migration command; the next save writes `{workspaces,quickPrompts}` through serialized temporary-file writes and rename (with bounded Windows sharing retries). These fields never touch Pi JSONL. Removing a workspace unregisters it without deleting the directory or Pi JSONL; active or waiting sessions block removal. On mobile the first screen separates existing workspace cards (open one) from an explicitly titled Add a workspace form (browse or enter a new server folder, then Add & open). Unavailable paths are collapsed separately and can be removed from the registry. Settings for the selected workspace are separately collapsed under Edit selected workspace. Choosing a workspace opens its session list, while a session opens Chat/Execution. Back links return to Sessions and Workspaces without ending the selected Pi session or its stream. Mobile browser/Android Back and Forward use real History API entries for workspace list, session list, Chat, Execution and Settings; the entries retain exact selected workspace/session IDs without changing the Pi JSONL. Settings can be loaded directly at `/?view=settings`. Rename/pin controls remain behind Manage workspace. Desktop keeps its simultaneous rail/Chat/Activity layout.

## Session UX

Sessions list by running-first then file modification time, with title/ID search, timestamp and active indication. Pi's `session_info.name` wins; absent that, the first user text in the first 128 KiB of session JSONL provides a trimmed deterministic title; absent that, the abbreviated ID is displayed. No AI title generation. Running sessions not yet persisted in Pi JSONL remain in the server's active list. Session switching resumes by exact workspace and session ID. One server may own multiple Pi workers. A stopped worker can be reopened through the existing resume route; an interrupted prompt is never automatically resent.

## Chat, mobile navigation and copy

Mobile navigation has three levels: Workspaces → Sessions → a single session; only within a session do Chat and Execution appear as two tabs. Desktop uses a compact workspace/session rail, a primary conversation canvas and an independent Activity panel. A dark, block-based visual language with restrained violet accents draws on modern terminal UX without copying Warp assets. Source IDs and raw metadata are available under Details instead of occupying the default Activity view. The selected workspace and session stay visible in the session header, and the return links provide direct navigation without loading a new browser page. The composer is multiline: desktop Enter sends, Shift+Enter inserts a line, Ctrl/Cmd+Enter sends on either platform, mobile Enter inserts a line; Send and Stop are separate touch-size controls with explicit enabled/running feedback. Esc stops an active run from the focused composer. Ctrl/Cmd+K opens/focuses session search while the console has focus; this intentionally overrides Chrome's address-bar search shortcut on that page. Quick prompts are editable (0–8, up to 200 characters each), default to three starter phrases, and **insert only**; they cannot accidentally submit. User messages, assistant text and safe fenced code rendering include Copy all and Copy code buttons. Copy uses secure-context Clipboard API and shows success/error feedback. No remote Markdown HTML is inserted. Scrolling follows new output only while near the bottom; otherwise New content / Jump to bottom is shown.

## Settings and browser-local preferences

The settings page follows pi-web's section-list/detail pattern, with Sessions, Automatic cleanup, Start with Windows, About the app, Language, Appearance and Pet sections. Sessions chooses the default view when opening a session (Chat or Execution); About the app describes Pi Console, links its third-party notices, and reports the current browser connection and visible workspace/session counts. Language switches the settings page and navigation between English and Japanese; **other controls and chat content remain English**. Appearance chooses Violet or Graphite. Pet shows/hides an animated Codex-compatible sprite, selects a package, scale and side. It discovers `pet.json` + `spritesheet.webp` (or a manifest-named PNG/WebP) in `~/.pi/agent/pi-console/pets/`, `~/.codex/pets/`, then `~/.pi/agent/pi-web/pets/`, preferring Fio (`fio-observer`) in Auto mode when installed. It supports 8-column V1 (9 rows) and V2 (11 rows) atlases with idle/running/waiting/review/failed/completed rows; only actual canonical Pi run and decision state is used (no fabricated approval). The pet alternates calm idle pauses (a slow blink with brief closed-eye frames) and short, slow walking bouts, using Codex right/left walking atlas rows according to actual movement direction. Touch/mouse dragging plays the matching walk row more briskly, then returns to idle on release. Other observed Pi statuses have separate frame durations for working, waiting, review, failure and completion. Motion rows change without reloading the atlas. It bounces at safe travel limits and by default avoids the mobile composer/navigation area. Drag it with a finger or mouse to reposition it anywhere within the viewport (excluding the mobile navigation bar). Dragging pauses wandering for 15 seconds, after which it wanders only near the dropped position; the position is saved in this browser and clamped again on resize/orientation changes. Reduced-motion preference disables automatic movement but not dragging. No pet artwork is copied into this repository; on this machine Fio is installed in the user's Codex pet folder, while on other machines a compatible package must be installed. `/api/pets` and `/api/pet/file` remain protected by the same Host/Cloudflare Access verification as the other APIs and serve only strict, bounded package manifests and image assets, with realpath containment to block symlink escapes. These presentation preferences are validated and stored in browser `localStorage` (`pi-console:preferences:v1`), not shared across devices, pi-web, Pi sessions or server metadata. If browser storage is unavailable, changes last only until reload. A browser reload restores the selected view/workspace/session from its history entry; browser Back never closes or stops a Pi worker.

## Active sessions, tool progress and instruction navigation

The authenticated `GET /api/activity` endpoint reports only sessions already open in this server's RuntimeManager: a Pi run or observed running Execution node, and/or an exact waiting decision node (`decisionCount`). It never scans all JSONL files to infer a live worker or an approval. The workspace landing screen shows a bounded active-session inbox across workspaces (input-needed first), with exact workspace/session links. Session lists include the same observed decision count and running state for opened workers. The browser refreshes the read-only inbox every five seconds and on local run/decision transitions; when a worker stops or the server restarts, historical activity is not presented as live. “Need input” is a notification only, not an unverified Approve/Deny protocol.

A running Pi tool displays its observed tool name and a bounded, single-line preview of explicitly supplied command/program/script/code/path arguments. Tool progress and completion retain the original invocation preview; unsupported inputs fall back to the tool name. An empty assistant message instead shows that running tool, or an honest generic processing state when no specific action is known. A completed tool-only message with no text says there was no text reply. No tool output or invented program name is synthesized.

The assistant bubble's Copy all control is below the bubble, with a mobile-size touch target; code-fragment copy remains by its code block. Instructions · N in the conversation heading opens a bounded, scrollable list of this session's user messages (latest first; 80 initially, older pages on request). Selecting an instruction scrolls and focuses that exact message in Chat without resending it or changing Pi JSONL.

## Session recycling (Windows)

Each session row has an explicit Move to Recycle Bin action with a confirmation. The Automatic cleanup settings page provides server-side retention, **disabled by default**, preset to 30 days and adjustable from 1 to 3650 whole days. Enabling checks immediately, on server start, and hourly thereafter. Age is measured from the Pi JSONL file's filesystem modification time; up to 50 candidates are attempted per check. The policy is saved separately in `.pi-console/session-retention.json`, not browser localStorage. Both manual action and server policy are behind the same Access JWT / Host / Origin checks as other APIs.

Only real Pi session JSONL files in registered workspaces, within the configured session root, are eligible. Identity (header ID and cwd), realpath containment, regular-file status and age are checked before moving. A session this server observes running or waiting for input is excluded, as is one being opened or recycled. Automatic retention also skips all sessions open in Pi Console, including idle sessions; a manual action can close an idle worker first. The native Windows Recycle Bin is invoked on fixed local drives; no fallback to permanent deletion is allowed. If the Recycle Bin is unavailable, the operation fails and reports an error. Since Pi's session directory is shared with other Pi clients (including pi-web), those clients will also stop seeing recycled files. Pi Console cannot identify every independently running worker in other applications; check this limitation before enabling automatic retention. No JSONL contents are edited and no Pi sessions are moved until the server-side switch is enabled (manual action is independent).

## Start with Windows

The package includes `package/startup.mjs` and a managed `Pi Console.lnk` in the **current Windows user's** Startup folder. The shortcut runs the package from its root with Node's optional `.env` loader, so the same loopback/Cloudflare Access configuration is used after sign-in. It does not start Pi's TUI, create a Windows service, or bind a public interface. If the loopback port is already occupied, the launcher exits without touching the existing process. Pi package installation has no post-install hook: on the first trusted interactive Pi `session_start` after installation the extension registers the shortcut, and never from an RPC worker. The Start with Windows settings page can install immediately or turn it off and remove only a shortcut with the package's owner marker; disabling persists in the agent directory and prevents future extension loads from reinstalling it. An unrelated same-name shortcut is not overwritten or removed. The authenticated `GET/POST /api/startup` endpoints own the server-side state; no path is accepted from the browser. Startup is a sign-in convenience, not a process monitor or reboot-time service.

## Prompt execution target

The composer defaults to **Pi (direct)** for every selected session. When the installed ludi-agent-kit exposes its programmatic API, the user may explicitly select **ludi-agent-kit orchestrator**. Send then starts a separate kit run with the server-verified workspace path and exact Pi session UUID (`clientContext.kind: 'pi-web'`, the binding supported by the installed kit). It does not ask the language model to decide whether to call the tool. The kit owns model routing and its run store; the server tracks the current in-process job and the existing bound snapshot adapter projects run/tasks into Execution. The kit job cannot be stopped with Pi Stop, accepts no browser attachments, and does not write a Pi chat message. Status kept in this server's memory is lost after a restart, but a bound kit snapshot can still be reprojected when its Pi session is reopened. A newly created Pi session without any Pi prompt may not have a persisted JSONL yet; use a persisted Pi session if recovery after restart matters. Missing kit disables the option; choosing it alone makes no model call.

## Model, thinking, context and attachments

The session controls use Pi RPC `get_available_models`, `get_state`, `get_available_thinking_levels` and `get_session_stats`; selections call `set_model` and `set_thinking_level` on the exact active session worker. Changes are blocked while a prompt is running. Context shows Pi's reported `contextUsage.percent` with tokens/window after a model response; it displays an unknown state instead of fabricating a percentage when Pi has no measurement. After a settled run the UI refreshes the reading.

The browser can attach at most four files to a prompt: UTF-8 text (64 KiB per file) or PNG/JPEG/GIF/WebP images (5 MiB per image, 8 MiB decoded total). Text is included in the Pi prompt and persisted in Pi's session; images are passed as Pi RPC `ImageContent` with base64 data. The same-origin authenticated POST validates filename, MIME/content signature, count and size; it never writes an upload to the server or reads a client-supplied server path. Unsupported binary files, such as PDFs, are explicitly rejected. The request body is capped at 12 MiB only for `/api/prompt`; other JSON endpoints keep their 1 MiB cap.

## Execution and decisions

Execution remains the server-owned state tree with Unattached roots where source parentage is not known. Chat displays active, failed, blocked and decision-needed counts. Running tool nodes remain visible while completed tool rows are hidden by default; owners can show history/details. Completed agent/task descendants can be collapsed; failed/blocked/decision nodes offer Copy context. History renders only the latest 200 entries initially, with older pages on request; metadata is not expanded by default. Decision-needed has a prominent text count and context copy but no Approve/Deny action because no structured response protocol was confirmed. Failure cards identify event source and entity, raw summary/status, and offer restoration of the last submitted prompt for **manual** retry. Reopen session is offered on a failed worker. A historical failure is not automatically retried or misrepresented as non-terminal.

## Reconnect behavior

The connection label distinguishes Browser offline, Server unavailable, SSE reconnecting, Pi process stopped, Pi process failed, runtime healthy and no-session server ready. SSE errors close the stream; a bounded retry timer checks the server, fetches a current snapshot and opens a new stream. If the server restarted and no state exists, the existing `/api/resume` path reopens the exact session, rehydrates Pi chat and validated Orchestrator state, and then reconnects. A gap in canonical sequence triggers a snapshot. Server unavailable is not shown merely because a live server could not resume a particular session; that remains a visible operation error. A browser reload does not replay prompts or infer a new relationship. Foreground child progress and in-memory Pi execution nodes cannot survive a server restart (Phase 2 limitation).

## PWA and persistence

Manifest provides standalone display, start URL, 192/512 PNG icons and a maskable icon. Same-origin service worker precaches index, versioned assets discovered in it, icons and manifest; navigation uses network-first with cached shell fallback. API and SSE are **never cached**. Offline shell displays Server unavailable and Reconnect; it cannot run Pi offline and does not cache session data. Chrome's Playwright incognito context reports only `in-incognito` in installability diagnostics; manifest, icon sizes, service-worker registration, cached assets and offline launch were checked. Actual home-screen installation on a physical phone was not tested. Workspace and quick prompts share the existing local metadata file; Pi JSONL and the Orchestrator's SQLite keep their existing ownership. The presentation preferences listed above live only in browser localStorage; execution events are not persisted beyond the existing bounded stores.

## Verification and limits

`npm test` covers metadata migration/validation, deterministic titles and ordering/search, quick-prompt validation, code fences, command preview, connection state, existing canonical/reducer and fake-Pi HTTP/activity tests. `npm run test:real` exercises actual Pi. Playwright desktop/mobile uses actual Pi for prompt/tool/stop/copy and a separate fixture-backed long-session probe (350 messages/1200 canonical events). PWA check verifies Chrome installability errors excluding the test-only incognito restriction. With many messages, Chat retains all DOM nodes (350 checked); no virtualization was added. Source adapters do not expose full child tool lifecycles, guessed Orchestrator parentage, or an approval transaction. All functionality remains loopback-only and local-server dependent.
