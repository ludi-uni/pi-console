# 操作シナリオ・状態文言・受入条件

## 画面遷移と表示

| 状態 | 主に見える文言 | 次の操作と保持するもの |
| --- | --- | --- |
| 初回・本人未確認 | 「Dots連携を設定します。最初にConsoleの管理者本人を確認してください。」 | 「本人確認へ」。目的draftがあれば保持。認証完了を全権限許可と扱わない |
| 初回・本人確認済み | 「Dotsに任せたいことと対象を選んでください。」 | 目的→登録workspace。不要な親folder・本文共有の欄は必須にしない |
| workspaceが空 | 「登録されたワークスペースがありません。」 | 「既存workspaceを登録する手順」「新しいrepoを作るための許可を設定」。この表示だけでdirectory／repoを作らない |
| session未観測 | 「このワークスペースは登録済みです。選んだsessionの準備が必要です。」 | 明示準備、または別の登録workspaceを選ぶ。選択行を隠さない |
| path／観測が不明 | 「対象の安全性／現在のsessionを確認できません。操作はまだ許可できません。」 | 同画面で再確認、選択変更。別pathやsessionに自動切替しない |
| 接続準備中 | 「接続を準備しています。完了した確認は保持しています。」 | 次に必要な本人PC確認／clientの一操作だけ。戻る・中断は使える |
| 権限不足 | 「接続は確認できましたが、このsessionへの操作は未許可です。」等、不足項目を特定 | 「この対象への操作を確認」。本人不足なら本人確認へ、folder不足ならfolder確認へ。全部を初回に戻さない |
| 許可済み・client確認待ち | 「許可は確定しました。client側の対象確認を待っています。」 | 対応clientの確認／再検出一手順。承認をもう一度押させない |
| 接続済み | 「この対象に、表示した操作を許可しています。」 | 対象・操作・各期限・接続の要約。「変更」「状態／解除」 |
| Pi権限だけ期限切れ | 「このsessionへの操作許可が期限切れです。転送は接続中です。」 | 同じ対象をdraftにして「期限と操作を再確認」。31日転送をPi期限へ使わない |
| 転送だけ切断 | 「操作許可の現在状態は表示のとおりです。転送が切れています。」 | 同じ帰属の接続再開／再確認。権限やキーを自動更新しない |
| 認証期限切れ | 「本人確認の期限が切れました。入力内容は保持しています。」 | 本人確認後、現在snapshotを照合。元の確認checkboxをそのまま再利用しない |
| 他の変更と競合 | 「現在の設定が変わりました。入力は保持しています。」 | 差分を確認→入力を保って再確認／現在値へ戻す。scopeを勝手に上書きしない |
| 戻る・中断 | 「設定は中断できます。確定済みの許可・準備したworker・転送は一覧で確認できます。」 | draftの中断で、それらを勝手に停止・解除しない。取り消すものを選ぶ場合は別確認 |
| 再開 | 「前回の未確認処理を照合しています。」 | 同じrequest結果を取得。二重作成／二重許可をしない。古い前提だけ再確認 |
| 部分失敗 | 「対象操作の許可は解除済み。転送の切断結果は未確認です。」等 | どこまで成功したかをreceipt別に表示。同じ結果の照合から始める |

これらの状態変更は入力中の段階を勝手に置換しない。警告・確定可否・次の本人操作を更新し、画面の移動は本人が選ぶ。

## 短いシナリオ

### 1. 登録済みworkspaceでPi操作補助を使いたい

「Dots連携」→「Piセッションの操作を手伝ってもらう」→プロジェクトAを選択。未観測sessionも理由付きで見え、「選んだsessionを準備」を本人が押す。操作と15分の期限を下書き。既存の帰属確認済み接続を使い、必要なら対応client側の申請を同画面の案内どおりに一度行う。対象・既存範囲への影響とexact操作許可を順に確認。client照合後に接続済み。親folder・本文共有を選ばずに終えられる。接続だけでPi指示を実行しない。

### 2. 許可する親folder配下でrepo／workspaceを作りたい

「repo／workspaceを作ってもらう」→親folderと許可操作・期間を下書き→接続を照合→その接続への親folder許可だけを確認。directory／local git init／登録の範囲を明示する。Pi操作補助が不要ならPi許可確認を通らない。実repo作成は接続設定完了とは別の本人依頼に従う。安全性を確認できないprovider／pathなら作成可能と表示しない。

### 3. 期限切れを直したい

同じ「Dots連携」の要約に「Pi操作の期限切れ、転送は接続中」。対象・操作を保って期限確認へ進む。現在のsession generationと既存変更を再照合してからその許可だけを更新する。既存Tunnelを再作成せず、接続を長くする選択を権限延長に使わない。

### 4. 入力中に外部から状態が変わる

期限欄に入力し、workspace一覧の途中へスクロールしている間に、遅れた応答と新snapshotが到着。入力値、選択、focus、IME、scrollを保持。旧sequenceは破棄し、有効な新snapshotは警告／差分へ保存する。対象が失効なら確定だけ停止し、再確認しても自分の入力を失わない。

### 5. 中断後に戻る

接続確認の途中で「中断」。再度「Dots連携」に入り、非秘密draftと未完了処理の参照から再開。失われた許可応答は元のrequestで照合し、既に許可済みなら二度確定しない。本人認証が切れていれば本人確認後に再照合する。workerや転送を閉じる操作を中断に混ぜない。

### 6. 他のMCP clientで同じ目的を使う

「他のMCPクライアントで使う」→同じ目的／対象／許可。対応clientの正式な設定経路だけを案内する。stdioならDots App/Tunnelを要求しない。unsupported機能は「client側で設定と照合が必要」と明示し、3本の人手キー生成を求めない。requestと内部credentialの分離は維持する。未照合のclientを接続済みにしない。

## 受入条件

UX合格は本人が上の主シナリオを自然に完了し、どの許可がいつ必要かを自分の言葉で説明できること。試験本数だけでは合格にしない。

| 領域 | 合格条件 | 証拠 |
| --- | --- | --- |
| 導線 | Dotsの設定入口は一つ。内部機能のタブ巡回や別ページ探索がなく、現在の目的に必要な順が分かる | 静的画面案への本人レビュー、後続のdummy walkthrough画像／操作記録 |
| 表記 | 主見出し・ボタン・statusに利用者個人の名前を出さない。日本語／英語でDotsという製品と一般MCPを区別できる | 文言一覧と両言語の画面確認 |
| 不要な確認 | Pi目的で親folderを、repo目的でPi／本文共有を必須にしない。必要な別権限は同じ導線で明示確認する | purpose別シナリオ、API receiptの範囲確認 |
| 入力の保持 | 連続60秒以上の編集に複数回の状態取得、遅延・順序逆転を混ぜても入力／選択／focus／IME／scroll／detailsが保持される。背景取得で操作をdisableしない | 1280px・390pxのdummy browser動画または連続画像、DOM／操作記録。実画面も別途本人確認 |
| freshness | old response、別target、別generation、別page epochを破棄。保持draftのままでも確定直前はfresh確認。revoke／expiryで許可を復活させない | fake providerの遅延・逆順・revoke・世代変更試験 |
| 操作衝突 | pollと本人操作のlockを分離。二重クリック・close後応答・応答喪失で準備／許可を重複させない。未確認処理は同じrequestで照合 | isolated dummy試験と操作記録 |
| 部分失敗 | 各別権限の結果を区別し、全成功や全取消を捏造しない。成功項目を勝手にrevoke／再実行しない | fake APIごとの成功／失敗組合せ、照合画面 |
| 権限境界 | owner、connection、workspace、parentfolder、exact control、read／finalが混同されない。他clientに影響する共有変更を明示。path等の既存安全境界を緩めない | public contractの差分レビュー、既存境界回帰。今回native/OS試験は増やさない |
| 接続 | 準備済み／許可済み／client照合待ち／接続済みを区別。対応が未確認のclient機能やApp bindingを保証しない | client能力の一次仕様・限定実証、dummy状態表。実連携は別本人操作 |
| 解除 | 一か所で対象と効果が分かる。実行中Pi、送信済み本文、作成済みrepoを消すと説明しない。部分解除未確認を隠さない | 解除確認・結果の画面レビュー、fake失敗ケース |
| 保持と秘密 | 復帰draftに秘密／cookie／JWT／本文を保存しない。URL/argv/log/公開endpoint/チャットへ秘密を出さない | 保存schema・network/log出力の限定レビュー、dummyデータ検査 |

## 実装の段階と停止点

1. **今回：退避と再設計。** 現状・権限境界、上記画面案・文言・更新契約を本人にレビューしてもらう。ここで停止。新UI codeを現在の実装に足さない。
2. **設計合意後：隔離prototype。** Aの目的ガイドと接続後要約をdummy状態だけで示す。本人に初回・期限切れ・中断再開を操作してもらい、導線と文言を評価する。実key／grant／Pi／native操作は不要。
3. **編集状態のモデル。** draft/snapshot/journal/viewStateを分離し、先に背景更新・古い応答・IME/focus/scrollのfocused回帰を作る。backend変更を同時に広げない。
4. **既存契約への接続。** owner／transport／各権限のadapterを最小限に組み込む。共有scopeへの影響と部分失敗の扱いを別レビューし、旧機能を単に丸ごと同居させない。一般stdioも回帰する。
5. **dummy受入と本人UX受入。** 本数だけでなく、目的別walkthrough、編集中更新、両言語、大小画面、戻る／中断／再開を証拠にする。本人が「日常的に操作できる」と確認した状態を記録する。
6. **別承認の実適用。** 具体的差分・保全・現在停止状態を示してから反映／再起動。実認証・key／grant・client／Piは必要なものだけ本人の明示操作で行う。今回の承認で先取りしない。

レビューで決めたいのは、Aの目的ガイドを主導線にすること、目的に不要な権限を外すこと、状態取得とdraftの分離、接続後の状態・解除の要約である。per-client storeへの変更や新しいtransport自動設定は、この案の承認へ紛れ込ませない。
