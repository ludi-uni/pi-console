# 使い方

[入口へ戻る](../README.md) · [English](usage.en.md)

## ワークスペースとセッション

1. Pi で `/pi-console` を実行し、表示された URL を開きます。標準ポートは `31717` です。使用中なら `/pi-console 31719` のように変更できます。`/pi-console stop` で Pi が起動したサーバーを止められます。
2. **Workspaces** で既存のワークスペースを選ぶか、**Browse folders**（または絶対パス）から登録します。ワークスペースはサーバー側の作業フォルダーで、独立した「プロジェクト」データはありません。スマートフォンのフォルダーではありません。
3. セッションを選ぶか新規作成し、**Chat** で Pi に指示を送ります。セッション内でモデルと思考レベルを選べます。**Context** には Pi が応答後に報告した使用量が表示されます。新規セッションは、最初の指示でファイルが保存されるまではサーバー内だけに存在します。

**Manage workspace** では表示名の変更・固定・登録解除ができます。登録を解除してもフォルダーや Pi セッションは削除しません。フォルダーブラウザーはサーバー上の現在のフォルダーにサブフォルダーを作れます。**Open on host PC** は登録済みのフォルダーをホスト Windows の画面で開きます。スマートフォンから押しても、スマートフォンのファイルアプリは開きません。

## 会話、添付ファイル、プレビュー

- ブラウザーから UTF-8 の小さなテキストファイル、または PNG/JPEG/GIF/WebP 画像を最大4個添付できます。Pi の思考とツール実行は会話内に分けて表示され、コマンドの詳細はタップで展開できます。**Instructions** から過去の指示へ移動でき、回答下の **Copy all** で回答をコピーできます。
- 回答は表・リスト・コードブロックを含む Markdown として表示します。生 HTML と外部画像は描画しません。
- 回答中の `.txt`、`.md`、`.markdown` と一般的なソース／設定ファイル（`.ts`、`.py`、`.go`、`.json`、`.yaml` など）は、選択中のワークスペース内にあれば読み取り専用でプレビューできます。本文、Markdown リンク、インラインコードのパスに対応します。ディレクトリー名付きの通常の文章なら、空白を含むパスも検出します。
- プレビューはワークスペース外（シンボリックリンクによる逸脱を含む）、バイナリ、未対応形式、256 KiB を超えるファイルを拒否します。編集・ダウンロードはしません。**Copy** は Markdown の表示結果ではなく元の本文をコピーします。コードには行番号が付き、`src/main.ts:42`、`src/main.ts:42:8`、`src/main.ts#L42` で指定行に移動できます。プレビュー内のリンクを辿った後は **Back** で戻れます。

## 実行状況と Orchestrator

- **Execution** に Pi のツールと確認できたフォアグラウンド pi-subagents、セッションに紐づく Orchestrator の活動が表示されます。紐付けを確認できない項目は **Unattached** 扱いです。承認を行う画面はありません。Pi が提供する場合、実行中のプログラムやコマンドも表示します。
- **Activity** にはサブエージェント、入力待ち、終了結果、最近の問題が表示されます。最近の項目はサーバーが保持する間（最大24時間）確認でき、問題は成功後または10分後に消えます。バックグラウンドの **Inspect background result** は拡張機能から取得可能な範囲の結果だけを表示し、失効した結果を復元しません。
- 互換性のある ludi-agent-kit がインストールされている場合、**Execution** から選択中の Pi セッション・ワークスペースに紐づく別の Orchestrator 実行を開始できます。Pi のセッションモデルとは別のモデル設定を使い、プロバイダー料金が発生し得ます。新規セッションには保存のための短い Pi 応答を先に生成し、終了後は短くまとめた結果を Pi に渡して通常の回答として保存します。これらもモデル呼び出しです。進捗は Chat にリアルタイム表示されますが、進捗そのものは会話に保存されません。詳細は Execution の kit 状態から再構成されます。
- Kit 実行中、同じセッションへの Pi 指示は一時停止します。**Execution** に質問が表示されたら選択肢（または自由記述）を送信できます。すべての質問への回答後、kit が自動で再開し、追加のモデル呼び出しが発生する場合があります。再開が失敗し、回答済みの同じ実行が再開可能なままなら、**Retry continuation** で回答を再送せずに再開だけ試せます。再試行もモデル呼び出しが発生し得ます。再開できない間は **Continue Pi chat while kit is paused** を選ぶと、その実行を保留したまま Pi の会話に戻れます。再試行中は再び Pi への指示が一時停止します。回答は kit のリポジトリー単位の判断記録にも残ります。kit は完了したが Pi の会話への最終報告だけが失敗した場合は、Execution の **Retry saving report to Pi** で報告だけを再送できます。この操作は kit を再実行しませんが、Pi のモデル料金が発生する場合があります。最終報告の失敗を解決するまでは、同じセッションで次の kit 実行を始められません。前回の送信結果が不明な場合は、二重投稿を避けるため再送を拒否し、Pi セッションの確認を求めます。送信結果が不明なら Pi の履歴と Execution の報告を確認し、再送せず次に進む場合に限り **Mark report handled after inspection** を選びます。確認ダイアログの承認後、報告は「手動対応済み（Pi への保存は未確認）」となり、再送はできなくなります。同じセッションで次の kit 実行を始められます。報告失敗と送信済みか不明な状態はデータディレクトリーの `report-recovery/` に保存し、サーバー再起動後も復元します。復元後に自動で Pi に再送することはありません。Pi セッションの削除やワークスペースの解除は未解決の報告がある間は拒否します。ブラウザーの添付ファイルと **Stop** は kit 実行には使えず、Pi Console から kit 実行をキャンセルすることはできません。Pi の通常の **Stop** は待機中の指示を消し、Pi に `abort` を送ります。

## モバイル、通知、設定

スマートフォンでは Workspaces → セッション一覧 → Chat / Execution の順に移動します。アプリ内の戻る操作とブラウザーの戻る／進む操作で一覧へ戻れますが、Pi ワーカーは停止しません。再接続してもワーカーは終了しません。PWA をインストールしてもオフラインでは使えません。

**Settings** では表示形式、外観、Codex 互換のペットなどを設定できます。言語切替は設定とナビゲーションを対象とし、アプリ全体を翻訳するものではありません。ペットは別途導入された `pet.json` とスプライトシートから見つかり、ドラッグで移動できます。**Sessions → Automatic cleanup** は、最終更新から指定日数が経った Pi セッションファイルを Windows のごみ箱へ移動します（標準では無効）。Pi セッションは他アプリと共有されるため注意してください。手動で1件ずつごみ箱へ移すこともできます。

**Sessions** の完了通知は、タブを開いたまま隠したときのブラウザー通知です。権限を求めるのは有効化したときだけです。終了時刻の予測や、ブラウザーを閉じた後の通知はありません。**Orchestrator settings** は初回のモデル割り当てと優先順位を設定でき、詳細なルートは Advanced に残ります。設定の詳細と保存先は [運用・開発ガイド](operations.ja.md)を参照してください。
